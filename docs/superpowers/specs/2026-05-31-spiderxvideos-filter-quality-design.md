# SpiderXVideos 过滤与画质设计

## 目标

在现有 `spiderxvideos` 接入基础上，补齐三类能力：

- 支持按关键词发起搜索抓取。
- 支持按文件大小和时长过滤，只保留满足条件的视频。
- 支持下载当前可获得的最好画质，优先保留高质量源，必要时可合并 HLS。

## 约束

- 现有 `spider91` 行为不变。
- 默认仍以直链 MP4 为主，避免破坏现有下载链路。
- 过滤条件是严格条件：不满足的条目不进入最终结果。
- 未知大小或未知时长时，若配置了对应过滤条件，则跳过。

## 设计

### 输入参数

新增驱动 / 脚本配置项：

- `keyword`
- `min_size`
- `max_size`
- `min_duration`
- `max_duration`
- `merge_hls`

保留现有 `start_url` 作为高级覆盖项。

优先级：

1. `start_url` 非空时，直接使用它。
2. 否则 `keyword` 非空时，构造 `https://www.xvideos.com/?k=<urlencoded keyword>`。
3. 两者都为空时，使用站点首页。

### 过滤规则

- `min_size` / `max_size` 支持字节和人类可读单位，如 `500MB`、`1.5GB`。
- `min_duration` / `max_duration` 支持秒数或 `mm:ss` / `hh:mm:ss`。
- 时长优先从详情页或列表元数据读取。
- 文件大小优先使用直链响应的 `Content-Length`；若拿不到且配置了大小过滤，则跳过。
- 过滤发生在入库前，只有通过过滤的视频才会进入 `videos` 结果集并计入 `target_new`。
- 被过滤掉的条目记日志并视为已处理，避免后续轮次重复消耗。

### 画质规则

- 默认 `quality=best` 仍保留。
- 无 `merge_hls` 时，`best` 只在直链源里选择最优 MP4 候选。
- 开启 `merge_hls` 时，`best` 可以优先选择 HLS，并由后端用 `ffmpeg` 合并为本地视频文件。
- `quality=hls` 仅在 `merge_hls=true` 时有效。
- 如果配置了大小过滤，HLS 仍然允许参与最终选择，但大小校验在下载后以实际文件大小为准。

### 后端职责

Go 侧继续负责：

- 调起 Python 脚本并传递新参数。
- 下载直链视频与封面。
- 当 Python 返回 HLS 且 `merge_hls=true` 时，调用现有 `ffmpeg` 配置完成合并。
- 下载完成后，按实际文件大小做最终校验。
- 只把通过过滤的视频入库。

### 前端职责

`DrivesPage.tsx` 为 `spiderxvideos` 增加：

- 关键词输入。
- 最小 / 最大文件大小输入。
- 最小 / 最大时长输入。
- `merge_hls` 开关。

`start_url` 继续保留为高级项，不覆盖现有使用方式。

## 错误处理

- 缺少关键词时，仍可用首页或 `start_url` 抓取。
- 时长无法解析且配置了时长过滤时，跳过。
- 文件大小无法确定且配置了大小过滤时，跳过。
- HLS 合并失败时，该条视频失败并继续下一条。

## 测试

- Python 单测覆盖：
  - 关键词生成搜索 URL。
  - 大小字符串解析。
  - 时长字符串解析。
  - 过滤只保留满足条件的视频。
  - `best` 在 `merge_hls` 开关下的选源顺序。
- Go 单测覆盖：
  - 新参数从后台配置传到 crawler。
  - HLS 合并分支和失败分支。
- 前端测试覆盖：
  - spiderxvideos 表单字段可见。
  - 新字段会写入提交 payload。

## 验收标准

- 可直接用关键词发起 xvideos 搜索抓取。
- 只有满足大小和时长条件的视频会进入最终结果。
- 开启 `merge_hls` 时，可以拿到比直链 MP4 更好的画质。
- 现有 xvideos 基本抓取能力不回退。
